## 3. Staging UX 수용검증

1. `https://mkrental.vercel.app/admin` 최고관리자 로그인 → 시스템 > 데이터 관리 > 백업·복원·초기화 > 백업 JSON 선택 복원.
2. 선택 전 단일 영역: `파일 선택` / `선택된 파일 없음` 확인.
3. 2026-10-20에 다운로드한 정상 Staging 백업 JSON 선택 → 버튼 오른쪽에 **같은 줄로 파일명이 표시**되고 별도 `선택한 파일:` 문구가 없는지 확인. 긴 파일명은 영역에서 생략되더라도 마우스를 올리면 전체 이름 확인 가능.
4. 동일 파일 재선택 → 파일명 유지, 파일 데이터 재인식. 다른 정상 백업 JSON 선택 → 이전 미리보기와 실행 확인 문구가 초기화되어야 함.
5. 잘못된 JSON 선택 → 오류 안내 + 파일명 `선택된 파일 없음`; 이전의 복원 대상과 미리보기 제거.
6. 정상 JSON 재선택 → 4개 범위 체크박스 및 미리보기 버튼 활성화. 범위 또는 추가/덮어쓰기 방식 변경 시 이전 미리보기가 소멸하고 새로 확인해야 함.
7. 본 UI 핫픽스 확인에서는 **실제 복원 실행 금지**. 이전에 성공·정리한 시험 카테고리로 다시 기존 레코드를 조작하지 않음.

## 4. 주요 8개 기능 회귀검증 (Production 승격 전)

| 구분 | 확인할 사항 |
| --- | --- |
| 1. 관리자 로그인·재인증 | 로그인 유지, 관리자 페이지 전환, 이메일 인증 1회 후 데이터 논리 검사 완료 |
| 2. 일반 사용자 로그인 | 로그인·약관 동의·사용자 화면 전환 정상 |
| 3. Device Trust | 기기 신뢰 등록·검사·정책 차단 정상 |
| 4. 대여 신청·관리 | 신청, 내역 조회, 관리자 승인/거절, 예약 충돌 방지 |
| 5. 자산 관리 | 목록·상세·카테고리 조회/수정, 기존 데이터 보존 |
| 6. 게시판·문의 | 공지·FAQ·문의 조회 및 답변, 첨부 보호 |
| 7. 사이트 설정 | 사이트 콘텐츠·약관·푸터·팝업 등 조회·저장 |
| 8. 데이터 관리 보안 | JSON 다운로드·미리보기·파일 표시, 감사 기록 보존, 전체 초기화 차단 |

이 중 파괴적 조작·관리자 권한 테스트는 반드시 Staging의 별도 시험 데이터로만 수행. 위 8개 항목을 최신 소스로 다시 PASS 확인하기 전에는 Production 승격 금지.

## 5. 실패 시 회복

- ZIP 적용·Vite 빌드가 실패하면 Production 발행 없이 중단하고 빌드 로그 제출.
- 브라우저에서 이전 파일 입력 UI가 보이면 Vercel 배포가 최신 커밋인지 확인하고 강력 새로고침.
- 미리보기가 잘못되면 실행하지 않고 JSON 파일명, 선택 범위, 복원 방식과 오류 메시지만 제공. 백업 원본의 개인정보·인증코드·토큰은 공유하지 않음.
- 기존 PostgreSQL 전체 백업 및 JSON 스냅샷을 보존하고 운영 데이터 전체 초기화는 시행하지 않음.
