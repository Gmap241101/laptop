# Phase 34 P0 — 이메일 인증 6자리 분리 UI Staging 배포·수용검증

## 1. 배포 전제

- 유일한 기준 ZIP: `rental-system-phase34-p0-backup-otp-ux-20261020_deployment_package.zip`
- 기준선: 직전 JSON 파일 선택 UX 수정 Full ZIP
- 기존 `E:\\project\\rental-system\\backups`의 DB 백업 파일은 절대 이동·수정·배포하지 않는다.
- Production 직접 승격 금지.

## 2. Staging 프런트엔드 배포

```powershell
cd E:\project\rental-system\test_new
.\deploy.ps1
```

배포 패키지 선택 `2`(직접 경로 입력), 새 Full ZIP 지정, Firebase 배포 `0`, Production 발행 `N`.

`deploy.ps1 v13.5` 빌드·해시 검사를 확인한다. 이번 변경은 프런트엔드 전용이므로 Heroku Backend 재배포 및 Migration이 필요 없다.

## 3. 시각 검증

Staging `https://mkrental.vercel.app`에 최고관리자로 로그인한 후 `시스템 > 데이터 관리 > 백업·복원·초기화 > 백업·데이터 안전검사` 이동.

1. 상단 설명문이 정확히 다음과 같은지 확인.
   `현재 데이터의 논리적 정합성만 검사합니다. 전체 DB 복원 검사는 지원하지 않으며, 전체 데이터 초기화는 계속 제한됩니다.`
2. 기존 하단 주황색 경고는 사라져야 한다.
3. `이메일 인증`과 `상태 새로고침` 버튼이 나란히 표시되어야 한다.
4. `이메일 인증` 클릭 후 **6개 칸**과 `확인 후 검증 시작`이 관리자 데스크톱에서 같은 행에 표시되어야 한다.

## 4. 기능 검증

1. 수신한 새 6자리 코드를 복사해서 **첫 번째 칸에 Ctrl+V**. 여섯 칸이 모두 채워지는지 확인.
2. 코드 1자리를 지웠을 때 실행 버튼이 비활성화되는지 확인. 다시 6자리를 채우면 활성화되어야 한다.
3. 키보드 좌우 이동, Backspace, 숫자 1자 입력 후 다음 칸 이동 동작 확인.
4. 확인 버튼을 한 번만 누르고 데이터 논리 검사 완료 여부 확인. 중간 실패 시 사용한 코드를 반복 입력하도록 요구하지 않아야 한다.
5. `상태 새로고침` 기능 확인.
6. JSON 백업·미리보기 등 기존 기능 회귀. 데이터 변경을 포함하는 실제 복원은 별도의 시험용 레코드가 없는 한 다시 수행하지 않는다.

## 5. 합격·차단 기준

- UX 4개 요청 모두 확인 PASS, 코드 붙여넣기·인증 성공 확인 PASS, 이전 핵심 기능 회귀 이상 없음 → Staging 수용검증 합격.
- 인증 실패, 실행 버튼이 6자리 전에 활성화, 중복 검증 요청, 전체 초기화 차단 해제, 주황색 중복 안내 잔존, 버튼 줄맞춤 이상 → 승격 보류.
- 전체 DB 실제 복원 검증은 이번 변경 범위가 아니며 `데이터 논리 검사 완료`를 복원 성공으로 판정하지 않는다.
