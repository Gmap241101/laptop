## 변경 내용

1. `server/src/mail/mail-scheduled-safety.mjs` 신설: 대여 상태·반납 예정일 변경이 일어나는 **기존 업무 DB 트랜잭션** 안에서만 관련 예약 알림을 점검한다. 원본 대여 건이 `대여중`이 아니거나, 반납일이 변경되었거나, 예약 실행일이 현재 서울 날짜와 불일치하면 `queued`/`retry` 상태만 `cancelled` 처리하고 오류 코드를 `mail_scheduled_rental_changed`로 기록한다. 이미 `processing`/`sent`/`uncertain`인 기록은 변경하지 않는다. 실패 시 업무 트랜잭션 전체 롤백한다.
2. 관리자 대여정보 수정·사용자 취소/반납 심사·대여상태 변경 및 사용자 직접 수정·직접 취소·자동 연장 승인의 여섯 경로에 위 함수를 연결했다. 기존 메일 이벤트 등록은 그대로 둔다.
3. 예약 대상 검색에 `r.id > $3` PostgreSQL 키셋 페이지네이션을 적용하고, 여러 페이지의 `FOR SHARE OF r` 조회 후 동일 이벤트 고유 키로 Outbox 등록한다. 기존 100건 상한으로 인한 후속 대상 누락 가능성을 보완했다. 1회 실행의 상한은 이벤트당 200페이지 × 페이지당 최대 100건으로 제한한다. 초과 시 `partial`을 반환하므로 수용 검사 시 확인이 필요하다.
4. `2026-02-30`과 같이 달력에 없는 날짜는 예약 실행 인자로 거부한다. 서울 일자 경계와 고유 키 중복 방지 규칙을 그대로 유지한다.
5. 신규 Gate A Mock 검증에서 19종 이벤트 카탈로그, 관리자 2종, 예약 2종, 205건 페이지 순회 및 같은 날짜 재실행, 상태 변경 시 트랜잭션 취소, 429 확정 거절, 외부 발송 잠금, 자동 실행 기본 OFF를 검사한다.
6. 기존 P1-06/P1-06.1/P1-07 관리자별 수신 지정, 대기열 취소, 디자인/템플릿/미리보기 기능은 유지한다.

## 유의사항 및 후속 미검증

- Gate A는 **실제 PostgreSQL 통합시험이 아니다**. 테스트는 Mock PostgreSQL 클라이언트/저장소로 수행된다. Gate B에서 실제 Staging 데이터를 통한 조회·로그·취소/트랜잭션 검증이 필요하다.
- 예약 알림 **자동 실행은 현재 기본 OFF**다 (`P106_SCHEDULED_ENQUEUE_ENABLED`을 설정하지 않는다). 별도의 활성화 승인이 있기 전까지 설정하지 말 것. 자동 실행 허용은 실메일 전송 허용과 별개다.
- 실메일 발송은 P1-03 `P103_REAL_DELIVERY_LOCKED = true`; 기존 서버 시작 경로에 실제 dispatcher가 연결되어 있지 않다. 실제 Brevo/Resend 요청, 시크릿 등록, DNS 변경, Production 배포는 금지한다.
- 서버가 하루 이상 정지돼 사전 알림 시점을 완전히 놓친 경우, 지난 날짜의 '내일 반납 예정' 메일을 **늦게 보내지 않는다**. 연체 알림은 현재 서울 날짜의 다음 실행 시 보완할 수 있다. 복구 지연의 사용자 영향 및 운영 활성화 정책은 Gate B/C에서 별도 판단해야 한다.
- `FOR SHARE`와 업무 상태 변경의 동시 수행은 실제 Staging 동시성 시험이 추가로 필요하다. 스케줄러가 단일 DB 트랜잭션을 오래 보유할 때의 응답 지연/데드락도 반드시 확인한다.
- 관리자 가입 승인 요청(`admin_signup_pending`)은 기존 Mock 통과 상태이지만 수동 승인 대기 계정의 실환경 E2E는 아직 검증되지 않았다.
- 발송 결과가 불분명한 경우 자동/수동 재발송 금지. 일일 발송 한도, 429/5xx/타임아웃 격리, 중복 제거는 P1-08 Gate B Mock 및 한정 실환경 검증에서 재확인한다.
- 이번 Gate A **신규 DB Migration 없음** (001~048 유지). 배포 후에는 `deploy.ps1` 정상 Vite 빌드 및 Staging Heroku 배포, 기존 업무 8개 영역 회귀검증 필요.
