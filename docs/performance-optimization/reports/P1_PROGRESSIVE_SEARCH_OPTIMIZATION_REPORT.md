# 검색 200건 상한 제거 및 순차 검색 적용 보고서

## 1. 작업 기준

- 기준 패키지: `rental-system-p2-firestore-access-audit-deployment-package.zip`
- 작업 목적: 검색 대상이 200건을 초과하면 201번째 이후 문서를 찾지 못하던 정확성 문제 제거
- Firestore Rules 변경: 없음
- Firestore 인덱스 변경: 없음
- npm 의존성 변경: 없음

## 2. 수정 대상

- 관리자 대여 신청 검색
- 관리자 회원 검색
- 사용자·관리자 공지사항 검색
- 사용자·관리자 FAQ 검색
- 일반 사용자 과거 대여 이력 검색

## 3. 기존 문제

기존 검색은 서버에서 최신 문서를 최대 200건만 받은 뒤 브라우저에서 부분 문자열을 검사했다.

```js
firestoreLimit(200)
```

따라서 전체 문서가 200건보다 많으면 검색어와 일치하는 문서가 201번째 이후에 있어도 검색 결과에 나타나지 않았다.

## 4. 수정 구조

신규 서비스 `src/services/progressiveFirestoreSearch.js`를 추가했다.

- Firestore 문서를 기본 100건 단위로 조회한다.
- 현재 페이지를 표시하는 데 필요한 검색 결과 수까지 순차 스캔한다.
- 다음 페이지 이동 시 이전 마지막 문서 커서부터 계속 조회한다.
- 같은 검색어·필터에서는 이미 검사한 문서를 다시 읽지 않는다.
- 검색어·탭·필터·카테고리가 바뀌면 캐시를 초기화한다.
- 화면 이탈 또는 검색 변경 시 늦게 도착한 결과를 상태에 반영하지 않는다.

핵심 호출 형태:

```js
await scanFirestoreMatches({
  collectionRef,
  constraints,
  startCursor: cache.cursor,
  existingMatches: cache.matches,
  targetMatchCount: currentPage * pageSize + 1,
  batchSize: 100,
  matchesDocument,
});
```

`+1`건을 확보해 다음 페이지 존재 여부를 판단한다.

## 5. 관리자 대여 신청 검색

다음 필드를 검색한다.

- 자산관리번호
- 자산 카테고리
- 신청자 이름
- 신청자 이메일
- 대여자
- 부서
- 사용 목적

대여 상태 탭과 빠른 필터는 기존 서버 쿼리를 그대로 적용한다. 검색 중에는 전체 페이지를 한꺼번에 읽지 않고 현재 페이지에 필요한 결과가 확보될 때까지만 추가 조회한다.

## 6. 관리자 회원 검색

다음 필드를 검색한다.

- 이름
- 이메일
- 부서
- 전화번호
- UID

회원 상태 필터를 서버 쿼리에 먼저 적용한다. 기존의 “최신 최대 200명” 안내는 전체 회원 순차 검색 안내로 교체했다.

## 7. 공지사항·FAQ 검색

고정 문서와 일반 문서를 분리해서 조회한다.

- 고정 문서: 전체 고정 범위를 검색
- 일반 문서: 현재 페이지에 필요한 결과 수까지 순차 검색

FAQ의 “현재 카테고리 내 검색” 옵션은 기존과 동일하게 `categoryId` 서버 조건을 적용한다.

공지·FAQ 검색 대상:

- 제목
- 본문 텍스트
- HTML 본문의 텍스트 변환 결과

## 8. 사용자 과거 대여 이력 검색

다음 필드를 검색한다.

- 자산관리번호
- 자산 카테고리
- 대여 시작일
- 반납예정일
- 사용 목적
- 상태

기존 “최신 최대 200건” 제한 문구를 제거했다. 현재 페이지 이후 결과가 존재하면 다음 페이지 이동 때 이전 커서부터 추가 검색한다.

## 9. 실시간 구독 변화

검색 모드의 공지·FAQ·신청·회원 조회를 `onSnapshot()` 최대 200건 구독에서 `getDocs()` 순차 조회로 변경했다.

정적 호출 위치 기준:

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| `onSnapshot()` | 34 | 32 |
| `getDocs()` | 47 | 48 |
| 전체 Firestore 호출 | 124 | 123 |

호출 위치 수는 실제 문서 읽기 수와 동일하지 않다.

## 10. 읽기 비용 특성

장점:

- 200건 이후 검색 결과도 찾을 수 있다.
- 다음 페이지에서는 이전 커서부터 이어서 읽는다.
- 일치 결과가 앞쪽에 많으면 전체 컬렉션을 읽지 않는다.
- 검색 중 지속 실시간 리스너를 유지하지 않는다.

주의점:

- Firestore 기본 기능만으로 임의 부분 문자열을 직접 검색할 수 없으므로, 검색어가 매우 희소하거나 1글자인 경우 전체 범위를 여러 배치로 읽을 수 있다.
- 검색 결과는 검색 실행 시점의 일회성 결과이며 검색 중 원본 문서 변경을 실시간 반영하지 않는다.
- 대규모 데이터로 성장하면 검색 토큰 인덱스 또는 전문 검색 서비스 도입을 검토해야 한다.

## 13. 프로덕션 빌드

`prebuild`의 Firestore 엄격 감사는 통과했다. 실행 환경에 `vite` 실행 파일이 없어 실제 Vite 빌드는 다음 오류로 종료됐다.

```text
sh: 1: vite: not found
```

실제 프로젝트 PC에서 `deploy.ps1`이 `npm run build`를 실행하므로 빌드 실패 시 게시 전에 중단된다.
