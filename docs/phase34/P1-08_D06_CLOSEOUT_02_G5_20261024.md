## 02. G5 실제 Clerk 관리자 보안 연동 (P1)

### 구현 범위
- **신규** `GET /api/admin/mail-delivery/g5-owner-check`.
- **기본값 OFF**. 서버에서 `APP_ENV=staging`이고 `P108_G5_OWNER_READONLY_ENABLED=true`로 명시한 경우에만 읽기 전용 API 준비. `APP_ENV` 실제 환경변수명/설정은 서버 설정 문서를 먼저 확인한다.
- 실제 G5 정책: RS256 서명·`azp` HTTPS 허용 출처·`sts=active`·토큰 만료·PostgreSQL owner/active/linked/잠금·5분 이내 서명된 재인증 증빙.
- 반환: `result=PASS`, `readOnly=true`, `emailsSent=0`, `vendorCalls=0`, `canSend=false`; 사용자 ID·JWT·메일주소·토큰값을 반환하지 않는다.
- Production과 비활성 상태: 404. 비인증/오류: 민감정보 없는 403. 쓰기 메서드: 405.

### 작업별 수용 기준
- [x] 오프라인 합성 RSA JWT/가짜 PostgreSQL 관리자 레지스트리 및 HTTP 경계 테스트.
- [ ] 기존 승인 절차에 따른 **Staging 변경 범위 확인·백업·배포 승인**. 아직 미배포.
- [ ] Staging 서버 환경이 정확히 `staging`인지·JWT 공개키/허용 HTTPS `azp`/pending 차단/clock skew 확인. 환경변수 원문·비밀키 공유 금지.
- [ ] 기능 플래그를 명시적으로 활성화 후 최고관리자 현재 Clerk 세션에서 실제 JWT를 서버에 전송해 PASS 확인. 토큰 원문 공유 금지.
- [ ] 재인증 전·5분 초과·owner 아닌 관리자·잠금·권한 강등·만료·출처 불일치·세션 변조 모두 403/오류 확인.
- [ ] 실제 Clerk 토큰이 `fva`, `reverification_id`, `sts`, `azp`를 발급하는지 확인. 누락 시 **FAIL-CLOSED**이며 무서명·사용자 JSON 대체 금지.
- [ ] 일반 관리자 로그인/로그아웃 및 기존 8개 업무 회귀 PASS.
- [ ] 기능 플래그 OFF 시 404 확인, 배포 전후 누락·토큰·개인정보 및 이메일 전송 0건 확인.

### 브라우저 검증 주의
사용자에게 JWT 문자열을 복사하도록 요청하지 않는다. 개발자 도구 Network에서 응답 HTTP 상태와 `g5OwnerCheck.result`만 확인하며 인증 헤더·쿠키·전체 HAR를 외부 공유하지 않는다. 실제 토큰 획득 UI는 현장 Clerk SDK 상태를 확인한 후 별도 확정한다.

### 최종 판정
실제 Staging JWT + PostgreSQL 관리자 권한 확인과 부정 시험 + 기존 업무 회귀 PASS가 모두 확인된 경우 **G5 종료**. 이번 오프라인 개발만으로 9/13 처리 금지.
