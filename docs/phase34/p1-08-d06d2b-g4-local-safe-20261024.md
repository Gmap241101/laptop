# Phase34 P1-08 D06-D2B G4-LOCAL-SAFE — PostgreSQL 세션 격리 보완

기준선: `D06-D2B-G4-LOCAL`, 2026-10-24.

## 변경 사유
기존 선택적 로컬 PostgreSQL 검증 러너는 풀에서 가져온 세션에 `SET search_path`를 적용했습니다. 풀 연결 재사용 시 영속 세션 설정이 잔류할 가능성을 제거하기 위해 트랜잭션 단위 `SET LOCAL search_path`로 수정합니다.

## 구현
- `createG4WrappedPool`은 `BEGIN`이 성공한 **같은 연결**에 `SET LOCAL search_path`를 즉시 적용하고, 이어지는 G2 SQL은 해당 트랜잭션에서만 실행합니다.
- `COMMIT`/`ROLLBACK`이 끝나면 PostgreSQL이 search_path 변경을 자동 해제합니다. 트랜잭션 완료 전에 `release()`가 호출되면 풀에 연결을 돌려주지 않고 폐기 대상으로 넘깁니다.
- `SET LOCAL` 실행 실패 시 먼저 `ROLLBACK`을 시도합니다. ROLLBACK도 실패하면 연결을 폐기합니다.
- 연결 문자열의 `?` 쿼리 옵션과 `#` 프래그먼트를 거부합니다. `host`·`hostaddr`·`service`는 별도 오류로 거부합니다. TCP 연결로 지정된 환경에서 PostgreSQL 측 IP가 로컬 루프백(`127.0.0.1` 또는 `::1`)이 아닌 경우 차단합니다.
- 기존 로컬 복원 DB 이름 화이트리스트, 임시 스키마 생성·제거, G2 승인 잠금, Brevo 선택/Resend 보존, 서버 런타임 분리, 실메일 전송 금지를 그대로 유지합니다.

## 오프라인 수용
`npm run server:phase34:p1-08-d06d2b-g4-local:smoke` 및 `npm run server:phase34:p1-08-d06d2b-g4-transaction-isolation:smoke`를 각각 PASS해야 합니다. 전체 `npm run verify:phase34`에 신규 검사를 연결했습니다.

## 현장 수용 조건 (미실시)
현재 검사 환경에는 PostgreSQL 서버가 없어 실제 SQL을 실행하지 않았습니다. Windows에서 **기존 복원 DB**의 자격증명을 로컬에서 설정하고 승인한 뒤 기존 `G4-LOCAL` 절차에 따라 실행해야 합니다. 시험 종료 후 임시 스키마가 남지 않았는지 카탈로그에서 재확인하고, stdout JSON 결과·종료코드·접속 DB 식별값(암호 제외)을 기록하십시오. 성공 후에도 Staging DB 마이그레이션/Clerk/메일 검증은 별도 수용이 필요합니다.

보안 주의: 로컬 주소·DB 이름 검사만으로 DB가 진짜 복원본인지 암호학적으로 증명할 수 없습니다. TCP 터널 등 전달 구성이 있다면 운영 DB를 대상으로 하지 않았는지 운영자가 독립적으로 검토해야 합니다. 사용자 Windows 환경을 이 작성 환경에서 원격 조작하지 않았습니다.
