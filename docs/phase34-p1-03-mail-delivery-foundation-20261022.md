# Phase 34 P1-03 — 기존 web dyno용 이메일 전달 엔진 기반 (2026-10-22)

## 개발 범위
- 단일 기존 Heroku PostgreSQL DB에서만 관리. 신규 DB, Redis, Worker, 애드온 및 외부 스토리지 사용 금지.
- `045_phase34_p1_03_mail_delivery_safety.sql`: `app_mail_delivery_attempts` 시도 로그(보수적인 무료량 예약), `app_mail_outbox`의 `uncertain` 상태·클레임 토큰, lease 인덱스. 기존 044 스키마 변경은 추가적인 확장만 수행.
- `mail-delivery-repository.mjs`: 트랜잭션과 전역 advisory lock으로 여러 web 실행 간 예약 직렬화. `FOR UPDATE SKIP LOCKED`로 하나만 클레임. 최근 24시간/30일 시도 수(성공/실패/불명확 포함)를 보수적으로 확인하고 허용량을 초과하면 대기. 중복 등록은 044의 `dedupe_key` 고유값 사용.
- 관리자가 유형을 OFF로 바꾼 뒤 기존 대기 건은 발송 시도 전에 취소. 사용자 취소·탈퇴 등 업무 별 수신제한은 P1-04/05와 연계해 추가 개발해야 함.
- Mock 성공은 외부 제공자 접수(`sent`)를 모의하며 배달 완료와 다름. 429 명확한 거부에만 지수 백오프 재시도. 타임아웃·네트워크 오류·5xx·리스 만료는 `uncertain`으로 분리하여 **자동 재발송 금지**. 400/401/403 등은 실패 종료. 불명확 시도도 발송량에 포함(보수적 무료량 계산).
- `mail-dynoweb-dispatcher.mjs`: 기존 web dyno 내 구현 가능한 인프로세스 주기 호출기와 Mock 전용 Dispatcher. **실제 서버 `index.mjs`에는 연결하지 않음**. 비활성 상태이며 외부 POST 메일 발송 기능 없음. 기존 P1-01 `MAIL_ENABLED=true` 등 환경변수로도 실발송 불가. 별도 승인 후에만 안전성 재평가 및 활성화 코드를 적용.

## 제한 및 추가 수용 게이트
- 실 운영 Brevo 계정, 발신 도메인 및 API 키 없음. 실메일 발송 0건.
- 기존 `app_mail_outbox` 생성은 아직 업무 트랜잭션에 연결되지 않음. P1-04/05에서 19종 상태 전이 연결을 개발해야 발생.
- DB Migration 045 실DB 적용, 기간별 카운터·원자성·lease 회복의 실제 PostgreSQL 통합 시험은 배포 전 Mock/정적 테스트만 수행. Staging 배포 후 별도 확인 필요.
- 운영 계정의 다른 시스템에서 보내는 메일은 이 DB에 기록되지 않으므로 한도 계산에 미포함. 실제 공급자 계정 한도 확인 및 안전 마진, 발송 쿼터 초기화 시각은 운영 전 검증 필수.
- Brevo 무료 플랜 일 300통, Brevo 초과 시 서버 측 1,000통 재시도 큐가 존재할 수 있어 300 미만 보수적인 별도 운용 한도도 검토. API 응답 'accepted'와 수신함 도착을 동일시 금지.
- 시뮬레이션 Mock은 실제 공급자 과금·한도를 소비하지 않으나 Staging에 개인정보를 기록하는 실제 시험은 사전 승인 없이 수행하지 않음.
- P1-06 관리 이력·재처리 승인 UX, P1-07 템플릿 시각 편집 보강, P1-08 실수신·운영 승격 게이트가 남음.

## 운영·보안 불변조건
- 새로운 환경변수나 사용자 설정만으로 잠금을 해제할 수 없음.
- 최고관리자 토글 OFF → 이미 큐에 들어간 대기 건까지 발송 차단.
- 실패 상세/수신 주소/API Key/템플릿 본문을 서버 진단 로그에 출력하지 않음.
- 최초 등록은 반드시 업무 원 트랜잭션 안에서 진행해야 함(현재 업무 연동 없음).
- Production 및 기존 Clerk 인증 메일 설정, Firebase 리소스 변경 금지.
