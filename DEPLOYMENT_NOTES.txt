배너·푸터 관리 UX 및 바로가기 롤링 수정 배포 안내

기준 패키지
- login_permission_state_sync_deployment_package.zip

이번 변경 범위
1. 메인 비주얼, 프로모션 배너, 바로가기 배너의 정렬 순서 숫자 입력을 제거했습니다.
   - 목록의 위·아래 이동 버튼만으로 순서를 변경합니다.
   - 등록, 수정, 이동, 삭제 시 현재 목록 순서를 1부터 연속 번호로 자동 정규화합니다.
   - 기존 데이터에 중복 정렬번호가 있어도 다음 저장·이동·삭제 시 실제 화면 순서대로 정리됩니다.
2. 배너 이미지에 표시 방식을 추가했습니다.
   - 영역 채우기: 기존 object-fit: cover 방식
   - 이미지 맞추기: object-fit: contain 방식
   - 이미지 초점 위치는 기존 가운데·위·아래·왼쪽·오른쪽 선택을 유지합니다.
3. 링크 입력 영역을 PC 기준 20% / 20% / 60%로 구성했습니다.
   - 링크 방식 20%
   - 탭 열기 20%
   - 외부 링크 주소 또는 내부 메뉴 60%
   - 현재 탭과 새 탭 열기를 배너별로 선택할 수 있습니다.
4. 푸터 메뉴 페이지 등록·수정 화면을 배너 관리와 같은 인라인 편집 카드로 변경했습니다.
   - 모달 오버레이를 제거했습니다.
   - 주황색 편집 헤더, 사용 여부 행, 취소·저장 버튼 배치를 통일했습니다.
   - 편집 중 다른 관리자 메뉴로 이동하거나 브라우저를 닫을 때 미저장 변경 경고를 표시합니다.
5. PC 바로가기 배너 롤링에서 7개 이상 등록 시 7번째부터 생략되고 첫 번째로 되돌아가던 문제를 수정했습니다.
   - 각 배너 그룹의 고정 50% 너비와 overflow:hidden을 제거했습니다.
   - 전체 배너를 포함하는 동일 그룹 4개를 연결하고 한 그룹 폭만큼 이동하는 연속 롤링으로 변경했습니다.
   - 모바일과 PC 모두 등록된 배너 전체가 순서대로 표시됩니다.
6. Firestore 경로와 Rules 권한은 변경하지 않았습니다.
   - 신규 필드 imageFit, openInNewTab은 기존 homeBanners 문서에 함께 저장됩니다.
   - 기존 문서는 필드가 없을 때 메인·프로모션은 채우기, 바로가기는 맞추기, 링크는 새 탭으로 호환됩니다.

배포 순서
1. 배포 패키지의 src 폴더를 프로젝트 src 폴더에 반영합니다.
2. rules/firestore.rules는 기준본과 동일하므로 기존 게시본을 유지할 수 있습니다.
3. 프로젝트를 빌드·배포합니다.
4. 배너 세 종류에서 신규 등록과 기존 수정 후 정렬, 맞추기, 탭 열기를 확인합니다.
5. 바로가기 배너를 7개 이상 사용함으로 등록하여 PC와 모바일 롤링 순서를 확인합니다.
6. 푸터 페이지 등록·수정 화면이 목록 위 인라인 편집 카드로 열리는지 확인합니다.

회원 로그인 권한 오류 수정 추가 안내

수정 대상
- 회원가입 정책에서 '등록된 부서·사용자만 가입 허용'을 해제한 뒤, 명부 불일치로 profileRequired 상태가 된 회원의 재로그인
- 서비스 운영 모드가 읽기 전용일 때 일반회원 로그인

수정 내용
1. 회원가입 명부 제한을 해제하면 directoryMismatch 사유로 profileRequired가 된 회원을 관리자가 즉시 원래 상태(active 또는 pending)로 복원합니다.
2. 회원 상태 복원 시 userAccounts와 accountRecoveryKeys의 accountStatus를 함께 동기화합니다.
3. 관리자 자동 복원에 실패하거나 이미 로그인 중인 회원은 다음 로그인에서 제한된 자기 상태 복원 규칙으로 복구할 수 있습니다.
4. 읽기 전용·점검 모드에서는 일반적인 명부 재검증 쓰기를 수행하지 않고 현재 회원 상태로 로그인합니다.
5. 정책이 해제된 directoryMismatch 상태 복원만 읽기 전용에서도 허용하며, 이름·부서·이메일 등 다른 필드는 변경할 수 없습니다.
6. 관리자·회원 본인의 userAccounts/{uid}, adminAccounts/{uid} 단건 조회 규칙은 유지됩니다.

배포 필수
- src와 rules/firestore.rules를 함께 반영해야 합니다.
- 소스만 배포하고 Rules를 게시하지 않으면 기존 profileRequired 회원의 자동 복원이 계속 permission-denied로 실패할 수 있습니다.
